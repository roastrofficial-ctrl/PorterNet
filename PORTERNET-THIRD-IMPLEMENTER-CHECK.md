# Third Implementer correspondence check

Date: 2026-09-30. Result: **the exercised correspondence boundary passes**.
Python and Rust independently agree on the complete Package's canonical bytes,
identity, possession, acceptance evidence and custody without translation.
The happy run and an eight-checkpoint interrupted run complete an opaque Return.
This is a fresh-store, one-correspondent/one-custodian experiment. It does not
claim that every PORTER schema or historical migration is now specified.

## What the complete journey established

1. Python publishes a real LG containing a Package with Unicode, a numeric value
   and an unknown envelope field. Native staging records an attempt and retains
   a Package Unit awaiting evidence.
2. Rust opens protected carriage, parses strict JSON, preserves the whole
   Package, verifies possession against retained local standing and commits AC.
   The harness stops to inspect AC's identity, complete Package and canonical
   digest before invoking any Host operation. CL and adapter files are absent.
3. Rust queues a separate protected AC receipt. Python validates and durably
   retains it. That knowledge does not collect the Package or run the Host.
4. A measured interval of at least 0.3 seconds contains six observations of no
   CL and no adapter start. Only the next explicit local attention command can
   publish/recover CL and offer its complete opaque Package.
5. The application fixture independently chooses a new opaque Return and uses
   Rust's real local LG operation. It receives no network route or carriage key.
   A deterministic Return identity makes repeated fixture offers idempotent;
   this is application policy, not runtime processing evidence.
6. Rust queues and protects the Return. Python verifies and commits a real AC.
   Its identity, canonical Package and digest match Rust's lodged Return.
   A second measured silence interval precedes Python's separately invoked
   HostRuntime visit, CL and adapter opportunity.
7. Return AC evidence travels in its own protected Unit and is retained by Rust.
   There is no synchronous response assumption on either leg. Original AC facts
   remain byte-for-byte unchanged across retries and both CL transitions.

The finite intervals establish observed silence in this harness. Structural
separation supplies the stronger causal fact: neither arrival entry point
invokes Host attention or an adapter. Participant operations run in distinct
processes; the experiment invokes attention separately. This is not evidence
about an untested long-running scheduler or arbitrary deployment.

## Interruption evidence

A successful happy run precedes the interrupted run. The latter visits all eight
requested checkpoints in sequence, inspecting facts before the next recovery.
Full literal facts, participant knowledge, responsibility, reconstruction and
unknowns are stored under `INTERRUPTION_FACTS` in the evidence log and extracted
into `evidence/third-implementer-interruptions.json`.

| Stop | Canonically true / responsibility | Knowledge and reconstruction | Still unknown at that boundary |
|---|---|---|---|
| After origin LG | LG; Python origin Porter | Origin knows LG; restart reconstructs outgoing Package | Remote AC and application action |
| After protected attempt | Same LG; Python origin Porter | Attempt exists; emitted frame is discarded; exact Package can retry | Origin has no evidence of remote AC |
| After recipient AC | AC; Rust recipient Porter | Rust knows AC; retry reconstructs inbox and original receipt | Origin acceptance knowledge; Host action |
| Before origin retains evidence | Same AC; Rust recipient Porter | Receipt exists only at recipient; origin remains acceptance-unknown | Origin has not retained AC evidence |
| After AC before attention | Same AC; Rust recipient Porter | Both Porters know AC; no CL or adapter start | Future attention and application meaning |
| After CL before offer | CL; Rust local Host custody | Adapter has not started; restart can offer the same CL | Application action |
| After Return LG | New LG; Rust origin Porter for Return | Python has no Return AC; original CL persists; LG reconstructs Return | Return acceptance and processing |
| After Return AC | New AC; Python recipient Porter for Return | Rust lacks returned evidence; replay reconstructs inbox/receipt | Python Host action and Rust's acceptance knowledge |

Rust stops use the existing durable-threshold interruption mechanism; Python
origin LG exits immediately after the LG interruption. The Return receiver exits
with `os._exit(23)` after production deposit commits AC and before receipt queueing.
After-CL and after-Return-LG exits leave their canonical facts intact. Stops after
frame emission, before receipt delivery and before attention are controlled
process boundaries. These are process/replay tests, not power-loss, filesystem
corruption or kernel durability tests (D-002 remains open).

## Attribution and compatibility

- **D-001: MULTIPLE.** Earlier documents permitted different serializers. The
  explicit JCS/binary64 decision differs from both old defaults; Python also had
  inconsistent possession and AC Unicode digests. Both were corrected.
- **D-006: MULTIPLE.** Earlier documents did not select either proof shape/HMAC
  message. The binding chooses lowercase digest hex as M and a structured proof.
  Rust required correction. The latest standing/source clarification changes no
  positive C, D, M or P bytes.
- **D-008: MULTIPLE.** A newly exposed wire gap: Rust sent its local AC; Python
  expected a receipt. The amendment chooses a compact receipt of original AC.
  Rust now constructs/verifies that shape. Python now rejects boolean/negative
  receipt time and an empty AC suffix.

These are representational bindings preserving Package possession and custody.
There is no peer-specific compatibility path, alternate digest or old-AC wire
fallback. Existing facts were not rehashed. Migration remains unimplemented.

## Validation and reproducibility

Evidence:

- `evidence/third-implementer-interop.txt`: all normative gates and both complete journeys.
- `evidence/third-implementer-rust.txt`: formatting, strict Clippy and 25 Rust tests.
- `evidence/third-implementer-python.txt`: 111 affected Python regression tests.
- `evidence/third-implementer-initial.txt`: initial round-trip failure retained.
- `evidence/third-implementer-manifest.json`: source bases, file hashes and image IDs.

The initial round-trip fixture recomputed its standing expiry on every process
restart, accidentally proposing different terms under the same Introduction.
It now supplies one fixed expiry. This was a fixture correction, not a standing
compatibility workaround. A Clippy item-order warning was also corrected.

From `systems/PorterNet`, build with the sibling Python checkout:

```sh
PORTER_REFERENCE_CONTEXT="$(cd ../porter && pwd)" docker compose build native-interop checks
docker compose run --rm native-interop
docker compose run --rm checks
```

Execution uses `network_mode: none`. The fixture moves protected frame bytes
between production entry points; it does not test TCP deployment. Rust fixture
clock values are logical constants, so expiration-clock interoperability is not
established. In particular, Rust standing currently compares Package expiry
seconds directly to `at_ms`; D-003 records this remaining defect for the next
validation pressure. Standing is provisioned locally; this is not an IN/SC exchange.
Adapter control return is never counted as processing success.
